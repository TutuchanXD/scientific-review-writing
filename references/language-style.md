# 中文语言风格

## 参考来源与用途

本文件提炼科研技术报告中的可复用表达习惯，用于探测器定标、性能测试和实验分析材料。公开版本不依赖特定本地文档，也不包含原始报告、实验数据或私人文件信息。

日常调用直接使用以下原则。用户另行提供文风参考时，只参考语体和表达习惯，不据此认定参考材料中的模型或性能结论已获验证。参考材料不决定新文档的科学事实、公式、方法、指标、参数、章节模板或论证深度。新材料需要更严格论证时，以当前证据和科学论证要求为准。

## 有依据的表达特点

| 观察到的写法 | 可复用原则 | 使用边界 |
|---|---|---|
| “本底修正”先说明电子读出结构及本底的空间、时间特性，再说明模型与数据如何参与修正 | 先界定对象与现象，再说明方法和作用 | 不把每段都写成“模块用于……” |
| “增益修正”围绕输入单位、转换操作、不确定度和输出单位展开 | 以具体量、操作和结果组织句子，保持单位和定义连续 | 原稿未展开的参数误差或条件不能因模仿风格而省略 |
| “宇宙线剔除”分步描述读取、归一化、建模、残差和识别 | 真实处理序列可使用明确步骤和顺序词 | 科学解释段落不强行改成操作清单 |
| “在轨定标数据处理”说明观测条件、测量过程和产物用途 | 将设计选择与其作用连接，保留必要的长句和解释 | 不继承具体采样数字、机制判断或方案成熟度 |
| “随机噪声分析”区分不同时间尺度及白噪声、相关项的处理 | 条件紧邻所限定的计算或结论 | 不能只模仿严谨措辞，仍须核实条件是否满足 |
| “测试与方案验证”结合各层测试所面临的问题说明验证内容 | 先交代测试理由，再描述测试动作与检查对象 | 不复制其固定测试层级或把软件测试结构套到探测器实验 |

## 目标语体

采用平实、正式、可审查的科研书面语。常见段落可从“对象或条件—方法或关系—结果或作用—必要边界”自然展开，但不要把它机械地套在每一段。

- 让读者知道主语是什么：探测器、实验数据、拟合模型、处理步骤或分析结果。避免“这一维度”“该层面”指代不明。
- 使用具体动词，如测量、拟合、估计、扣除、归一化、比较、约束、检验。动词按实际证据选择，不能为文风把“估计”改成“确定”。
- 保留必要的术语重复。同一物理量不要为了避免重复而改称另一个近义量；“稳定性”“重复性”“准确度”等依语义使用。
- 长句可用于连接条件、操作和结果。仅当主干、条件作用域或因果关系难以辨认时拆句；短句和长句不设配额。
- 数学表达前说明用途，之后解释变量、结果含义和条件。句中数学与独立公式按论证需要分工，不能用“由公式可知”代替关键解释。
- 使用“由于”“因此”“在……条件下”“随后”等词表达真实关系。步骤编号、条目和表格用于可比较或有顺序的内容；核心推理保持连贯段落。
- 适当保留“结果表明”“本节分析”等定位语，但避免相邻段落机械重复，且其后必须有明确内容。
- 结论语气与证据相称。定量结果、理论推断、候选解释和方案建议的语言强度有所区别。
- 分号用于确有并列关系且内部较复杂的分句。不要用分号串接背景、方法、结果和边界等不同层次的判断，也不机械地把所有分号替换为句号。
- 条件放在其限定的公式或结论附近。后文沿用同一条件时，可作简短指引，避免重复完整免责声明；作用范围改变时重新说明。

## 反防御性表达

先判断句子承担什么功能，再决定是否修改：

- **事实性限制**：样本量、适用范围、未验证条件和测量能力决定结论含义，须保留。“仅”“可能”“尚未”等词不作禁用词；不能为增强语气将估计、候选解释或条件性结论写成已证实事实。
- **有依据的负面结果**：未达到要求、性能下降或模型在特定条件下失效，可以直接报告。明确对象、指标、比较基准和范围，不把局部结果扩展成对整个方法的否定，也不以积极措辞掩盖它。
- **评价性措辞**：“遗憾的是”“必须承认”等作者姿态通常可去除；“价值有限”“存在严重不足”等判断须核查依据。缺乏依据时，保留其中的事实信息，去除额外评价；确有依据的评价改为具体问题及其影响，不能一律删成正面结论。若判断需要新的科学分析，按当前工作类型单列问题或进入科学修订。

重复限定按其作用域处理，条件位置遵循上文要求。摘要、结论等可能被单独阅读的部分仍需保留决定含义的限定；同一限制出现多次不自动等于冗余。不得将正文中影响判断的当前缺口改写成一句泛泛的后续工作。

审阅记录中的提醒不直接成为最终正文。基金申请中，获准科学修订后可将现有范围、未决问题与拟采用的研究办法连贯表述，具体取舍见 [基金申请论证](grant-proposal.md)。这种调整仍保留实际不利结果和影响结论的限制，不把“不能”“不是”等词机械列为禁词，也不以增加自我提醒句制造严谨感。

本节反防御性表达的选题参考 [Adkid-Zephyr/anti-defensive-writing-Skill](https://github.com/Adkid-Zephyr/anti-defensive-writing-Skill)，按科研评审中的证据、范围和修改权限要求重新制定。日常使用以本技能规则为准，无需加载上游技能。

## 章节衔接说明科学目的

在起草或获准调整组织时，章节开头承接尚未解决的问题，说明为何需要当前模型、推导或处理。章节结束交代所得认识，以及仍需下一步回答的问题。将衔接落在具体物理量、可观测量或判断依据上，不用“为后续研究奠定基础”等空话代替。

不要求每节都添加固定的开头和总结。已有论述能够自然衔接时沿用原结构，短小或逻辑直接的章节不重复概括。仅文风修订时，优先修正已有过渡句；若需要新增科学前提或重组章节，单独指出。

背景已明确的技术评审报告，可根据任务采用摘要式概述，集中说明评估目的、方法、主要结果及适用范围，将详细建模放在正文。是否采用这一结构取决于用户要求和模板，不将所有“引言”统一改为摘要。

## 最终报告的信息取舍

正文直接呈现当前采用的方法、结果及依据。仅用于记录改稿过程的旧版本对齐、内部讨论经过和已放弃的方法，通常留在工作记录中。历史比较若承担科学论证、需求追溯或受控修订用途，则按任务要求保留。实验顺序若影响时间漂移、迟滞或方法判断，也属于科学信息，不能按工作流水账删去。

用实验对象、观测时段、处理步骤和物理量名称指代数据与结果。原始文件名、路径、脚本变量及调试信息可移至数据说明、附录或复现记录；当文档本身说明数据产品或接口时，保留所需的精确名称。筛选范围、有效样本、统计口径等决定结果含义的信息不能以“专家不关心实现”为由删去。

内部讨论材料可帮助理解问题，其参考文献资格须由当前任务和实际来源决定。删除内部材料名称时，仍需保留最终结果所依赖的可核实依据，不能把来源不明的结论写成报告已验证的事实。

## 不从参考稿继承的内容

不迁移任务宣传、意义拔高、一般性前景描述、重复句或笔误。不要因为参考稿出现某个措辞，就把它设成新稿必须采用的风格。

不把“显著”“验证”“证明”“满足要求”当作普通修饰。它们在具体语境中可能承载统计、物理或验收含义，须有相应证据。不要把“有效”“充分”“系统性”等词一律禁用；只处理缺乏可检验内容的评价。

不导入参考报告中的工程配置、噪声目标、时间尺度、标定安排、阈值、接口或软件要求。若用户另行把该报告指定为科学依据，再针对本次问题读取对应内容，核对版本并区分原报告要求与新实验结果。

## 避免人为制造对立

不为强调正面判断而自行补出一个未出现的反面观点。例如，原材料只支持“该结果约束增益随温度的变化”，就直接这样写，不额外添加“不是简单的数值变化，而是……”。

允许有科学作用的否定：说明不可辨识性、指出当前数据未排除的解释、区分定义、报告检验结果。对于读者确有可能混淆的概念，解释差异所依赖的定义和条件，不只靠“不是……而是……”的语气强化。

## 文风修订的保守尺度

保留技术密度和书面语域。优先修改局部词句；不默认并句、重排段落、改章节标题或把论证变成要点摘要。

若用户另行要求缩写或摘要，明确交付物属于压缩版本，保留决定结论的假设和范围，不声称它与完整推导具有相同信息量。原始完整论证仍应保留在原文或用户指定位置。
